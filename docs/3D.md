# 3D in Valthorne

Runnable demos and assets are maintained in the public
[examples project](https://github.com/tehnewb/Valthorne-examples). Run demo launch tasks there; the engine's local
`src/examples/` files remain ignored and excluded from library artifacts.
See the [example catalog](examples.md). Historical measurements retain their
original commands and source revisions.

The 3D renderer uses the same application lifecycle, textures, asset manager, framebuffers,
and UI as 2D. Java 25 and OpenGL 3.3 are required.

For the new tiled lighting system, roughness/metallic materials, optimized shadows,
and live FPS display, see the [lighting guide](lighting.md). The lighting examples
below describe the compatibility render state; the new system attaches with `setLighting`.

## Try it

```shell
./gradlew run3DExample
./gradlew build
./gradlew run3DExample --args="--snapshot=build/3d-example.png"
```

Use `gradlew.bat` on Windows. The example generates its textures locally, displays a lit
scene with directional shadows and particles, and draws a 2D overlay. Left/right arrow
keys orbit, W/S zoom, clicking selects a model, and Escape exits. Snapshot mode renders
90 deterministic frames in a hidden window and saves the last frame.

`verify3D` runs the committed CPU and actual offscreen GPU tests independently of the
repository's ignored local demo/test sources. It requires an available OpenGL driver;
the rendering checks do not silently skip on machines without one.

## A scene in an Application

Create GPU objects in `Application.init()`, after JGL creates the context. Request a depth
buffer with `JGLConfiguration.defaults().depthBits(24)`.

```java
PerspectiveCamera camera = new PerspectiveCamera();
camera.setPosition(6, -8, 5);
camera.lookAt(0, 0, 0, 0, 0, 1);
camera.setClipPlanes(0.1f, 100f);

PerspectiveViewport viewport = new PerspectiveViewport(
        Window.getWidth(), Window.getHeight(), camera);
ModelBatch3D batch = new ModelBatch3D();
MeshRenderState3D state = new MeshRenderState3D().setCamera(camera)
        .setLightDirection(3, -4, 7)
        .setAmbientLight(new Color(0.2f, 0.2f, 0.2f, 1))
        .setDirectionalLight(Color.WHITE)
        .setFog(20, 80, 0.7f);

ModelInstance3D cube = new ModelInstance3D()
        .setModel(ModelBuilder3D.box(2, 2, 2))
        .setMaterial(new Material3D().setTint(Color.BLUE));
Scene3D scene = new Scene3D();
scene.add(cube);
```

In `update(delta)`, move or animate models. In `render()`:

```java
// Skip rendering while minimized (zero framebuffer dimensions).
viewport.update(Window.getWidth(), Window.getHeight());
Window.clear3D(Color.BLACK);
viewport.renderWithOverlay(
        () -> scene.render(batch, state),
        () -> { /* existing TextureBatch, fonts, shapes, or UI */ });
```

`Window.clear3D` clears both color and depth, including when the previous pass disabled
depth writes. `Window.clear` retains its color-only behavior. A `FrameBuffer(width,
height, true)` also supports the 3D renderer.

The viewport rebuilds the camera on binding and resizing. The model batch refreshes the
camera matrices at `begin` using its most recent viewport dimensions. For picking after
camera movement and before rendering, explicitly call `camera.rebuild(width, height)`.
The default overlay size follows viewport resizing; `setOverlaySize` fixes it to chosen
logical dimensions. Finish a 2D batch before switching between world and overlay.

## Coordinates and transforms

Built-in geometry uses **right-handed, Z-up** coordinates; XY is the ground plane.
Triangle fronts are counterclockwise. Camera defaults remain compatible with the 2D XY
plane (Y-up, looking along -Z). Use the six-argument `lookAt` above to orient a Z-up scene.
Screen projection and picking use a bottom-left origin, matching `Mouse.getY()`.

`setRotation(x, y, z)` accepts radians and applies X, then Y, then Z; `setYawRadians`
sets the Z rotation. `setRotation(Quaternionf)` supports arbitrary orientation.
An instance transform is `parent * translation * rotation * scale`. Negative scales
retain outward winding; normals use the inverse transpose for nonuniform scale and shear.
Mutating `getPosition()` or `getScale()` is supported and refreshes bounds on the next use.
Scale must be finite and nonzero.

`SceneNode3D` supports nested transforms with full matrix composition, including shear
from rotated children of nonuniformly scaled parents. Adding a child reparents it;
cycles are rejected. Invisible nodes hide their entire subtree. Add root nodes through
`scene.addNode(root)`; a node should occur only once in a scene hierarchy.

`Model3D` geometry is CPU-side and immutable through its public API. Instances borrow
models and materials. `ModelBuilder3D` builds boxes, planes, spheres, cylinders, or custom
triangles/quads. For streaming procedural shapes, use `MeshBatch3D` or a
`ProceduralRenderable3D`; its emitter receives the renderable so it can transform its
local vertices with `self.transform(...)` before writing world-space triangles.

## Materials, textures and transparency

```java
Texture diffuse = new Texture("assets/crate.png");
Material3D material = new Material3D().setTexture(diffuse)
        .setTint(Color.WHITE).setCullBackFaces(true);
cube.setMaterial(material);

Material3D glass = new Material3D()
        .setRenderPass(RenderPass3D.TRANSLUCENT)
        .setTint(new Color(0.5f, 0.8f, 1f, 0.35f));
```

Meshes interpolate UVs and per-vertex normals. The built-in triangle constructor without
normals generates flat face normals. Spheres and cylinder sides have smooth normals.
`setLightingMix(0)` makes a material unlit. Emissive color, fog contribution, radiance
contribution, culling, alpha cutoff, depth test and depth writes are configurable.

Opaque objects render first. Transparent meshes and billboards share one back-to-front
order, followed by additive effects. Selecting a transparent/additive pass disables
depth writes; `setDepthWrite` can explicitly override that afterward. Sorting uses object
centers in camera space, so intersecting transparent surfaces may require splitting
geometry into separate objects. Custom renderables can override `getSortDepth`.

Built-in model and billboard placements are copied at submission. A material is copied
on its first use within a frame. Set material properties before submitting it; use
separate materials for different appearances within that frame. Custom renderables and
texture regions must remain stable through `end()`. Explicit visibility remains effective
when `setCullingEnabled(false)` disables frustum culling.

3D draws restore the GL state they change, including depth, blending, culling, shader,
vertex/buffer bindings and texture units. Overlay drawing disables depth testing and
restores the surrounding state afterward. `Scene3D.render` and batch `end` recover from
exceptions; use `batch.cancel()` in a `finally` block when submitting manually.

## OBJ assets

```java
Assets.loadAsync(ModelParameters.fromPath("assets/ship.obj", "ship"), ObjModel3D.class)
        .thenAccept(model -> JGL.runTask(() ->
                scene.add(new ModelInstance3D().setModel(model))));
```

`ModelParameters.fromClasspath("models/ship.obj", "ship")` loads packaged assets.
The record also accepts a custom `ObjModel3D.Resolver` for memory, archives or other
sources; the resolver receives each dependency path relative to its referring OBJ/MTL.
Coordinates are preserved by default. Use `.withConversion(true)` to swap Y/Z, center
horizontally and ground the model. The existing `ObjModel3D.load(path)` convenience
retains that conversion; `load(path, false)` preserves coordinates.

Loading parses OBJ positions, UVs, normals, positive/negative indices, convex polygon
faces, optional RGB vertex colors, and MTL `Kd`, `d`, `Tr` and plain `map_Kd`. Polygon
faces are fan-triangulated. Missing normals produce flat normals. Vertex colors are
averaged per triangle. Material textures and color groups remain separate model parts;
instance tint multiplies imported tint, and an instance texture overrides imported textures.

Geometry and image decoding happen without GL. On first model-batch submission, textures
upload on the render thread; `uploadTextures()` can preload them there. OBJ instances
must go through `ModelBatch3D` to expand their imported material parts. Direct
`MeshBatch3D.model` draws geometry with the current single material.

Malformed indices report the source and line. Missing dependencies fail loading; MTL
texture transform options are explicitly rejected. Concave polygon tessellation, glTF,
and skeletal skinning are not provided by this renderer. The new lighting path adds
roughness/metallic materials; see the [lighting guide](lighting.md) for its scope.
For rigid-body simulation, colliders, sensors, and model synchronization, see the
[Jolt physics guide](physics3d.md).

## Lighting and shadows

The render state provides ambient and directional color, plus up to eight point lights
with range, color and intensity. A light direction points **toward the light**.

```java
state.addLight(new PointLight3D().setPosition(2, -1, 3)
        .setColor(Color.RED).setRange(10).setIntensity(2));

ShadowMap3D shadows = new ShadowMap3D(1024);
shadows.getCamera().setPosition(5, -5, 10);
shadows.getCamera().lookAt(0, 0, 0, 0, 0, 1);
shadows.getCamera().setWorldHeight(20);
shadows.getCamera().setClipPlanes(0.1f, 100);
state.setLightDirection(5, -5, 10).setShadowMap(shadows);

// Each frame before the main scene draw:
shadows.render(scene);
```

The light camera defines a directional shadow volume. Fit its height and clip planes to
the region that needs shadows. The map supports opaque/alpha-cutout meshes, 3x3 PCF
filtering, configurable bias and strength, and per-material casting/receiving flags.
Transparent objects and billboards do not cast shadows. Point lights are unshadowed.
The shadow pass restores framebuffer, viewport and the state it changes. Render a static
shadow map again only when its geometry or light camera changes.

The existing radiance texture integration samples XY world coordinates. It remains a 2D
light field projected onto 3D geometry, not a volumetric global illumination solver.

## Sprites, particles and animation

`BillboardSprite3D` accepts existing `TextureRegion` objects, including atlas regions or
frames selected by the 2D animation system. Choose spherical camera-facing orientation
or cylindrical Z-up orientation; set position, size, anchor, tint and material.

```java
ParticleEmitter3D emitter = new ParticleEmitter3D(500, particle -> {
    particle.setLifetime(2);
    particle.getPosition().set(0, 0, 1);
    particle.getVelocity().set(0, 0, 3);
    particle.getAcceleration().set(0, 0, -2);
    particle.getSprite().setTextureRegion(sparkRegion).setSize(0.2f, 0.2f);
}).setEmissionRate(50);
// update: emitter.update(delta);
// between batch.begin/end: emitter.submit(batch);
```

Emitters pool particles, enforce capacity, support bursts and continuous emission,
integrate velocity/acceleration and expire particles. Call `setEmitting(false)` to stop
new births while existing particles finish; `clear()` removes them immediately.

`TransformAnimation3D` applies reusable local transform tracks to instances or scene nodes.
Keyframes start at time zero and have strictly increasing times, finite positions, unit
quaternion orientations and nonzero scales. Position/scale interpolate linearly; rotation
uses shortest-path SLERP. Scale signs cannot change between frames.

```java
TransformAnimation3D motion = new TransformAnimation3D(
    new TransformAnimation3D.Keyframe(0, new Vector3f(), new Quaternionf(), new Vector3f(1, 1, 1)),
    new TransformAnimation3D.Keyframe(2, new Vector3f(0, 0, 3),
        new Quaternionf().rotationAxis(1.5f, 0, 0, 1), new Vector3f(1, 1, 1)));
motion.apply(cube, elapsedSeconds, true); // true loops; false clamps at the final frame
```

## Picking and resource ownership

```java
Rayf ray = viewport.screenToRay(Mouse.getX(), Mouse.getY());
PickResult3D hit = ray == null ? null : scene.pick(ray);
```

Picking returns the closest model triangle in world units, including transformed nodes.
The result includes the world hit position and node (for hierarchical models). Hidden
models/subtrees are excluded. Picking is geometric; it does not sample alpha textures
or pick billboards. JOML `Intersectionf` and `AABBf` provide ray/triangle and ray/bounds tests.

Dispose model batches, shadow maps and uploaded OBJ assets on the GL thread in the
application's `dispose()`. Batches own their supplied sub-batches. Scenes, instances,
materials and particle emitters borrow models/textures; removing an object never frees
shared assets. OBJ models own their decoded images and uploaded textures. User-created
textures remain caller-owned. Plain `Model3D` and builders hold only Java memory.

For direct static mesh rendering, build geometry, call `upload()`, then
`renderUploaded(state)` each frame. Repeated uploads/draws retain the CPU buffer contents.
The batch owns one GPU buffer; uploading or streaming different geometry replaces its contents.


Math types in these examples are imported from "org.joml" and "org.joml.primitives". See [JOML migration](joml-migration.md).
